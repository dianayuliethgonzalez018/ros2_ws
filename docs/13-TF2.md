# Entrada 13 - TF2

## Objetivo

Comprender por qué un robot necesita conocer la relación entre sus diferentes sistemas de coordenadas y cómo **TF2** permite representar y consultar esas transformaciones en ROS 2.

---

## La pregunta que me hice

Hasta ahora hemos trabajado con diferentes componentes de un robot.

Por ejemplo:

* Ruedas.
* LIDAR.
* Cámara.
* IMU.
* Base del robot.

Pero apareció una nueva pregunta:

> Si cada sensor se encuentra en una posición diferente del robot, ¿cómo sabe ROS 2 dónde está cada uno?

Para entender este problema primero debemos hablar de sistemas de coordenadas.

---

# El problema

Imaginemos un robot móvil que tiene un LIDAR instalado sobre su estructura.

Podemos representar el centro del robot mediante un sistema de coordenadas:

```text
              x
              ↑
              |
              |
        y ← Robot
```

Sin embargo, el LIDAR se encuentra físicamente en otra posición.

```text
              LIDAR
                ●
                |
                |
              Robot
```

Cuando el LIDAR detecta un obstáculo, la medición se realiza respecto al sistema de coordenadas del propio sensor.

El problema aparece cuando queremos utilizar esa información para mover el robot.

Necesitamos conocer:

```text
¿Dónde está el LIDAR respecto al robot?
```

Y cuando el robot comienza a desplazarse aparece otra pregunta:

```text
¿Dónde está el robot respecto al mundo?
```

ROS 2 necesita una manera de relacionar todos estos sistemas de coordenadas.

Para resolver este problema utilizamos **TF2**.

---

# ¿Qué es TF2?

**TF2** es el sistema de transformaciones utilizado por ROS 2.

Permite mantener y consultar las relaciones entre diferentes sistemas de coordenadas a lo largo del tiempo.

Estos sistemas de coordenadas reciben normalmente el nombre de **frames**.

Por ejemplo, en un robot móvil podemos encontrar:

```text
map
 │
 └── odom
      │
      └── base_footprint
           │
           └── base_link
                │
                ├── base_scan
                │
                ├── wheel_left_link
                │
                └── wheel_right_link
```

Cada nombre representa un frame diferente.

La relación entre ellos indica dónde se encuentra cada componente respecto a otro.

---

# ¿Qué es un frame?

Un **frame** es un sistema de coordenadas utilizado como referencia.

Podemos imaginarlo como unos ejes asociados a una parte del robot.

```text
        x
        ↑
        |
        ●────→ y
```

Por ejemplo, `base_link` normalmente representa el sistema de referencia principal del cuerpo del robot.

Un sensor puede tener su propio frame:

```text
base_link
    │
    └── base_scan
```

En este caso, `base_scan` puede representar la posición del LIDAR respecto al cuerpo del robot.

---

# Parent frame y child frame

Las transformaciones de TF2 relacionan dos frames.

Uno actúa como **parent** y otro como **child**.

Por ejemplo:

```text
base_link
    │
    └── base_scan
```

Aquí:

```text
Parent: base_link
Child:  base_scan
```

La transformación describe la posición y orientación de `base_scan` respecto a `base_link`.

Esta relación contiene principalmente:

* Traslación en X.
* Traslación en Y.
* Traslación en Z.
* Rotación.

---

# Árbol de transformaciones

Una de las ideas que más me ayudó a entender TF2 fue pensar las transformaciones como un árbol.

En un TurtleBot3 podemos tener algo parecido a:

```text
map
 │
 └── odom
      │
      └── base_footprint
           │
           └── base_link
                │
                ├── base_scan
                ├── imu_link
                ├── wheel_left_link
                └── wheel_right_link
```

Esto permite relacionar información proveniente de diferentes partes del robot.

Por ejemplo, aunque una medición del LIDAR esté expresada respecto a `base_scan`, TF2 puede conocer la relación entre:

```text
base_scan → base_link
```

y también entre:

```text
base_link → odom
```

De esta manera los diferentes componentes de ROS 2 pueden interpretar los datos dentro de un sistema de referencias común.

---

# Transformaciones estáticas y dinámicas

No todas las relaciones entre frames cambian.

## Transformaciones estáticas

Una transformación es estática cuando la relación entre dos componentes permanece fija.

Por ejemplo, el LIDAR está atornillado al robot.

```text
base_link
    │
    └── base_scan
```

Mientras el sensor no cambie físicamente de posición, esa relación permanece constante.

Estas transformaciones se publican normalmente en:

```text
/tf_static
```

---

## Transformaciones dinámicas

Otras transformaciones cambian mientras el robot se mueve.

Por ejemplo:

```text
odom
  │
  └── base_footprint
```

Cuando el robot avanza o gira, su posición respecto a `odom` cambia.

Estas transformaciones se publican normalmente en:

```text
/tf
```

---

# Explorando TF2 en ROS 2

Primero podemos comprobar si existen los topics relacionados con TF2:

```bash
ros2 topic list
```

Entre los resultados deberíamos encontrar:

```text
/tf
/tf_static
```

Podemos observar las transformaciones dinámicas utilizando:

```bash
ros2 topic echo /tf
```

Y las transformaciones estáticas mediante:

```bash
ros2 topic echo /tf_static
```

La cantidad de información puede ser bastante grande.

Esto ocurre porque un robot puede estar publicando varias transformaciones continuamente.

---

# Consultando una transformación específica

TF2 incluye herramientas que permiten consultar directamente la relación entre dos frames.

Por ejemplo:

```bash
ros2 run tf2_ros tf2_echo base_link base_scan
```

Con este comando estamos preguntando:

> ¿Cuál es la transformación entre `base_link` y `base_scan`?

La salida contiene información de traslación y rotación.

Podemos encontrar algo conceptualmente similar a:

```text
Translation:
x: ...
y: ...
z: ...

Rotation:
x: ...
y: ...
z: ...
w: ...
```

La traslación indica la diferencia de posición entre los frames.

La rotación indica la diferencia de orientación.

---

# Visualizando el árbol de TF2

Cuando existen muchos frames puede ser difícil entender las relaciones leyendo `/tf` directamente.

Podemos generar un árbol de transformaciones con:

```bash
ros2 run tf2_tools view_frames
```

Esta herramienta analiza las transformaciones disponibles y genera una representación de las relaciones entre frames.

Esto permite detectar más fácilmente problemas como:

```text
Un frame desconectado
```

o:

```text
Una transformación que no existe
```

---

# TF2 en TurtleBot3

En TurtleBot3, TF2 es especialmente importante porque diferentes componentes necesitan compartir información.

Podemos encontrar frames relacionados con:

```text
base_footprint
base_link
base_scan
imu_link
wheel_left_link
wheel_right_link
odom
```

El LIDAR realiza mediciones desde su propio frame, mientras que la odometría describe el movimiento del robot utilizando otros frames.

TF2 permite relacionar toda esta información.

Podemos imaginar el flujo así:

```text
LIDAR
 │
 ▼
base_scan
 │
 │ TF2
 ▼
base_link
 │
 │ TF2
 ▼
odom
```

Más adelante veremos que esta relación resulta fundamental para visualizar correctamente el robot en RViz, construir mapas mediante SLAM y realizar navegación autónoma.

---

# Un error que ahora tiene más sentido

Durante las pruebas con robots es posible encontrar errores relacionados con transformaciones.

Por ejemplo, una herramienta puede estar esperando:

```text
base_link → base_scan
```

pero esa transformación no existe.

Aunque el sensor esté publicando datos correctamente, ROS 2 no sabe cómo relacionarlos con el resto del robot.

Por eso, cuando aparecen problemas de visualización, una de las primeras cosas que podemos comprobar es:

```bash
ros2 topic list
```

Después:

```bash
ros2 topic echo /tf
```

o consultar directamente:

```bash
ros2 run tf2_ros tf2_echo base_link base_scan
```

Esto ayuda a determinar si el problema está realmente en el sensor o en la relación entre los sistemas de coordenadas.

---

# Lo que aprendí

Al principio veía nombres como:

```text
base_link
base_scan
odom
map
```

sin entender por qué existían tantos.

Ahora entiendo que representan diferentes sistemas de referencia del robot.

También comprendí que:

* Un **frame** representa un sistema de coordenadas.
* TF2 mantiene las relaciones entre esos frames.
* `/tf` contiene principalmente transformaciones que pueden cambiar con el tiempo.
* `/tf_static` contiene transformaciones estáticas.
* Los sensores necesitan estar correctamente relacionados con el cuerpo del robot.
* TF2 será fundamental para RViz, SLAM y Navigation2.

La idea que me queda es:

> TF2 permite que diferentes partes del robot puedan entender dónde están unas respecto a otras.
